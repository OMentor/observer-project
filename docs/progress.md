## Этап 2 — Доступ ✅

**Статус:** завершён. Модель доступа (пресеты), токены, участники и история
реализованы в backend, web и mobile; e2e подтверждает матрицу прав.

### Backend — готово ✅

- **Пресеты**: `Preset { FULL, OWN, BUSY, READ }`; владелец всегда FULL.
  `SpacesService.getAccess` возвращает `{ isOwner, preset }`.
- **Guard**: `PresetGuard` + декоратор `@RequirePreset([...])` с определением
  пространства по ресурсу (space/source/event/member/token); подключён в цепочку
  `JwtAuthGuard → RolesGuard → PresetGuard`.
- **Маскировка событий**: BUSY — все «Занято»; OWN — чужие «Занято», свои
  полностью; READ — полные данные без изменений; приватные источники скрыты для
  не-FULL.
- **Ownership**: правка/удаление события — FULL всегда, OWN только свои.
- **Токены** (`/spaces/:id/tokens`, `/tokens/batch`, `/tokens/:token/activate`,
  `DELETE /tokens/:id`): `randomBytes(32)` base64url, хэш sha256; одноразовая
  активация (атомарный claim → 409 при повторе; 400 для отозванных/истёкших);
  пакет до 100; управление только FULL.
- **Участники** (`/spaces/:id/members`, `PATCH/DELETE /members/:id`): список,
  смена пресета, мягкое исключение; владельца изменить/исключить нельзя.
- **История событий**: журнал CREATED/UPDATED/DELETED с автором и old/new;
  недоступна для маскированных событий.
- **Тесты/сборка**: 48/48 unit, `build` ✅, `lint` ✅.
- **Контракты**: обновлены `openapi/openapi.yaml` (34 пути, 27 схем) и

### Этап 7 — повторяющиеся события (Фаза 7.2) ✅

- **API**: `PATCH/DELETE /events/:id` принимают `scope` (`single`/`all`) и
  `occurrence_at` в теле или query; для серии без scope — `400`. RRULE
  валидируется через `rrule` (проверка `freq`), а не только длиной строки.
- **Сервис**: `scope=all` меняет/удаляет серию (при DELETE — вместе с
  исключениями), `scope=single` делает upsert `EventException` только по
  переданным полям; история (`event_history`) пишется в той же транзакции,
  push ставится для родительской серии.
- **Синхронизация**: pull разбирает `EXDATE`/`RECURRENCE-ID` (включая
  группировку `recurrences` у `node-ical`), push собирает один `.ics` с
  `RRULE`, `EXDATE` и override-`VEVENT`; исключения синхронизируются даже при
  неизменном ETag родителя, устаревшие synced-исключения удаляются.
- **Конфликты**: при `forcePush` серии исключения передаются в сериализатор,
  чтобы не потеряться при разрешении конфликта.
- **Проверка**: jest **192/192** (29 suites), `tsc`, ESLint и `nest build` —
