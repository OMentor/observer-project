# Синхронизация и конфликты

Реализуется на этапе 6. Здесь — согласованная логика.

## Провайдеры и адаптеры

| Провайдер | Протокол | Библиотека |
|-----------|----------|------------|
| Яндекс, Mail.ru, Apple | CalDAV (логин/пароль) | `tsdav` |
| Google | Google Calendar API (OAuth) | `googleapis` |
| Microsoft | Microsoft Graph (OAuth) | `@microsoft/microsoft-graph-client` |

Credentials сохраняются в `external_connections` в зашифрованном виде (AES-256-GCM).

## Модель владения

- Источник (`sources`) принадлежит пространству и виден участникам (если `SHARED`).
- Внешний календарь подключает конкретный пользователь (`external_connections.user_id`).
- Связь источника с внешним календарём — таблица `source_external_map`.
- Личные источники и записи видит только автор; владелец решает, кому шарить.

## Направления

`source_external_map.sync_direction`: `BOTH` | `IMPORT` | `EXPORT`.

## Правила

| Ситуация | Действие |
|----------|----------|
| Создано у нас | отправить во внешний |
| Создано во внешнем | подтянуть к нам |
| Изменено у нас | отправить |
| Изменено во внешнем | подтянуть |
| Изменено везде | конфликт (`sync_conflicts`) |
| Удалено у нас | удалить во внешнем |
| Удалено во внешнем | удалить у нас |

## Воркер

BullMQ, отдельный процесс (`pnpm start:worker`). Интервал — каждые 5 минут.
Читает изменения по `sync_token`, применяет к БД, отправляет локальные изменения,
обновляет `sync_token` и `last_synced_at`.

## Разрешение конфликтов

`POST /sync/conflicts/:id/resolve` — варианты: «наша версия» (`LOCAL`),
«внешняя версия» (`EXTERNAL`), «объединить» (`MERGE`). Пользователь уведомляется
(WebSocket + уведомления), на этапе 7 — через DeepSeek с предложением варианта.
