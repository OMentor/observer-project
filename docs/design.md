# Дизайн-система «Плетение»

Источник истины по токенам и компонентам для Web и Mobile.
Макеты в Figma (логотип, палитра, отступы, состояния) — отдельным артефактом;
в текущем окружении Figma недоступна, поэтому значения зафиксированы здесь и
синхронизированы с реализацией (`web/src/index.css`, `mobile/lib/core/theme`).

## 1. Бренд

- Название: **Плетение** (кодирует «сплетение» расписаний из разных источников).
- Идея: переплетение нитей-календарей в единое полотно.
- Логотип: стилизованная решётка из переплетённых линий (черновик — следующий
  шаг DS; пока текстовый логотип в шапке/на экране входа).

## 2. Цветовые токены

| Токен      | Светлая    | Тёмная     | Назначение                    |
|------------|------------|------------|-------------------------------|
| `bg`       | `#FAF8F5`  | `#1A1A1E`  | Фон приложения                |
| `surface`  | `#FFFFFF`  | `#25252B`  | Карточки, панели, шапка       |
| `border`   | `#E7E3DC`  | `#34343D`  | Границы, разделители          |
| `accent`   | `#5B5FEF`  | `#5B5FEF`  | Основные действия, активное   |
| `accent-2` | `#F0A030`  | `#F0A030`  | Акценты, предупреждения       |
| `success`  | `#34C77B`  | `#34C77B`  | Успех, подтверждения          |
| `conflict` | `#E05C4A`  | `#E05C4A`  | Ошибки, конфликты, удаление   |

Инверсия `on-accent`/`on-surface`: `#FFFFFF` на светлой, `#F5F3EF` на тёмной.

### Палитра источников (цвет по умолчанию: `accent`)

Рекомендованный набор для источников (сохраняется в поле `Source.color`):

```
#5B5FEF #F0A030 #34C77B #E05C4A #2BB3C0 #9B5DE5 #F15BB5 #8D99AE
```

Контраст текста на фоне — не ниже 4.5:1 (WCAG AA); на цветных метках
используется белый/тёмный текст по вычисляемой яркости.

## 3. Типографика

| Роль        | Семейство (fallback)                      | Размеры            |
|-------------|-------------------------------------------|--------------------|
| Sans (UI)   | General Sans → system-ui/Segoe UI/Roboto   | 13/14/16/18/20/24  |
| Serif (бренд)| Instrument Serif → Georgia               | заголовки, логотип |
| Mono        | JetBrains Mono → ui-monospace/Consolas     | время, коды        |

Шкала: `h1` 24–30 (serif), `h2` 20, `body` 14–16, `caption` 12–13.
Начертания: 400 (обычный), 500 (medium), 600 (semibold).

## 4. Пространство, сетка, радиусы

- Базовый шаг: **4px** (Tailwind-шкала 1 = 4px).
- Внутренние отступы: карточки 16px; панели 24px.
- Скругления: `lg` 8px (контролы), `xl` 12px (карточки), `full` (метки/аватары).
- Тени: минималистичные (1 уровень); границы предпочтительнее теней.

## 6. Состояния и паттерны

- Пустое состояние: центрированный текст-подсказка + действие.
- Загрузка: спиннер (Web — центр/кнопка; Mobile — `CircularProgressIndicator`).
- Ошибка: текст `conflict`-цвета рядом с формой или Snackbar.
- Подтверждение удаления: диалог (следующий этап — мягкое удаление уже в API).
- Приватность источника: метка «Общий»/«Приватный».

## 7. Доступность

- Фокус-ринг: `accent` (Web — `focus:border-accent`).
- Все поля имеют `label`/`htmlFor`/`labelText`.
- Контраст текста ≥ 4.5:1; интерактив ≥ 24×24px.
- Тёмная тема — по умолчанию (`ThemeMode.dark`); светлая поддержана.

## 8. Этап 2 — доступ (пресеты, токены, участники, история)

Модель доступа: участник пространства имеет один **пресет** (роль доступа),
владелец всегда FULL.

| Пресет | Код   | Видит события          | Меняет события            | Источники/токены | История |
|--------|-------|------------------------|---------------------------|------------------|---------|
| Полный | FULL  | полностью              | любые                     | создаёт/удаляет  | доступна|
| Свой   | OWN   | свои полностью, чужие — «Занято» | только свои       | —                | своих   |
| Занят  | BUSY  | только «Занято»        | нет                       | —                | нет     |
| Чтение | READ  | полностью              | нет                       | —                | доступна|

Маскированное событие (BUSY, а также чужие при OWN): заголовок заменяется на
«Занято», описание/место пусты. Цвет метки события — `muted` (`#8D99AE`),
карточка приглушена (`opacity`).

Компоненты этапа:

- **Переключатель пространства** (Space picker) — выпадающий список на страницах
  токенов/участников; на Mobile — вход через действия в шапке пространства.
- **Токены** — список активных токенов с колонками «Пресет, Создал, Создан,
  Действует до, Статус»; создание одиночного токена и пакета (до 100); единоразовый
  показ значения токена с копированием и готовой ссылкой `/activate/<token>`;
  отзыв — с подтверждением.
- **Участники** — список с именем/почтой, смена пресета через селект, исключение
  (мягкий отзыв). Владелец помечен и защищён от изменения/исключения.
- **Активация** — экран по ссылке `/activate/<token>`: вход (при необходимости),
  опционально имя, подтверждение; успех показывает выданный пресет.
- **История события** — панель с журналом (Создано/Изменено/Удалено, автор,
  дата, переход заголовка `старый → новый`); отдельная страница «История» (Web)
  с выбором события.

Статусы токена: **Активен** (`accent`), **Использован**/**Истёк** (`muted`),
**Отозван** (`conflict`).

## 9. Этап 3 — UI/UX (темы, отзывчивость, календарь, формы)

Задача этапа — довести интерфейс до состояния UI-беты: переключаемая тема,
адаптивный каркас, сводный календарь с фильтрами и перетаскиванием, аккуратные
формы и страницы настроек/профиля.

### 9.1 Темы

- Тема переключаема: **Светлая / Тёмная / Системная**. Светлая — по умолчанию.
- Web: `zustand`-стор темы (`pletenie.theme`) + `applyTheme`, класс `dark` на
  `<html>`; против «мигания» при загрузке — inline-скрипт в `index.html`.
- Mobile: `themeModeProvider` (`ThemeMode.system|light|dark`) + `ThemeMode` в
  `MaterialApp`.
- Токены `:root` / `.dark` (см. раздел 2); переключение мгновенное, без перезагрузки.

### 9.2 Каркас и отзывчивость

| Ширина        | Web                                                      |
|---------------|----------------------------------------------------------|
| `< lg`        | Скрытый сайдбар, кнопка-гамбургер открывает drawer       |
| `≥ lg`        | Постоянный сайдбар слева, контент справа                 |

- Переключатель темы — в шапке (иконка солнце/луна).
- Active-состояние пунктов меню — `accent`; на Mobile — `NavigationBar`/drawer.

### 9.3 Сводный календарь (Web)

- Панель фильтров над календарём: **пространство**, **источник**, **поиск по
  названию** (клиентская фильтрация). Выбор источника подстраивается под
  выбранное пространство.
- Легенда-чипы источников кликабельны (быстрое включение/выключение).
- **Drag-and-drop и resize** событий (`interaction` plugin): перенос меняет
  дату/время, растягивание — длительность; запрещены для чужих/маскированных
  событий (rights по пресету).
- Маскированное «Занято» — `muted`, без правки.

### 9.4 Формы события

- Web: React Hook Form + Zod (`eventFormSchema`); проверка `конец > начало`
  (`superRefine`); источник, дата/время, весь день, место, описание; удаление
  при наличии права.
- Mobile: нижний лист `EventFormSheet` (те же поля, создание/редактирование).

### 9.5 Страницы настроек и профиля

- **Настройки пространства**: имя (react-hook-form, keyed by space id), цвет,
  список участников-ссылок.
- **Профиль**: имя/почта, **выбор темы** (segmented: Системная/Светлая/Тёмная),
  блок внешних подключений (Google/Microsoft/Яндекс/Mail.ru/Apple) — заглушки
  «Скоро», активация токена, выход.

### 9.6 Новые/обновлённые компоненты

| Компонент        | Web                    | Mobile               | Назначение                       |
|------------------|------------------------|----------------------|----------------------------------|
| Переключатель темы | `ThemeToggle`        | `SegmentedButton`    | Светлая/Тёмная/Системная         |
| Панель фильтров  | `CalendarPage` filters | `_Filters` в календаре | пространство/источник/поиск    |
| Фильтры токенов  | `TokensPage`           | -                    | статус/preset/автор              |
| Фильтры истории  | `HistoryPage`          | -                    | источник/поиск/действие          |

## 10. Что осталось по DS

- Отрисовка логотипа и макетов экранов в Figma (внешний артефакт).
- Анимации переходов между экранами (следующий шаг; пока — базовые).
- Диаграмма состояний конфликтов синхронизации (для этапа 5).

## 11. Real-time (Этап 4)

- **Индикатор подключения** (Web — `ConnectionIndicator` в шапке; Mobile —
  `RealtimeIndicator` в шапке календаря): цветная точка + подпись
  «Подключение…» (accent-2, пульсация) / «Онлайн» (success) / «Офлайн» (muted).
- **Всплывающие уведомления (toasts)** — Web (`Toaster`, стек снизу-справа,
  автоскрытие 5 c, тона info/success/warning/danger); Mobile — глобальные
  `SnackBar` через `scaffoldMessengerKey`.
- Уведомления не показываются для собственных действий (сравнение `actor_id` с
  текущим пользователем).
- Обновление данных — фоном (инвалидация запросов/провайдеров), без визуальных
  «прыжков» интерфейса: список/календарь перерисовываются точечно.
